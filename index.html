Allocation Algorithms

Three classic strategies for fitting processes into available memory partitions.

01

First Fit

Scans memory blocks sequentially from the beginning and selects the first block that is large enough to satisfy the process request. Fast and simple; tends to leave large free blocks near the end.

Fastest lookup
02

Best Fit

Searches all available blocks and selects the smallest block that is still large enough for the process. Minimizes wasted space per allocation but may create many small, unusable fragments.

Minimum waste
03

Worst Fit

Searches all available blocks and selects the largest available block. The leftover remainder is maximized, making it more likely that the remaining space can serve future requests.

Largest remainder
This simulator uses the variable-partition model. Free space remaining after allocation is external free space, not internal fragmentation.
About

About This Project

MemoryOS® is an educational simulator designed to demystify how operating systems manage memory. Built as part of an OS coursework project, it lets students and curious learners interact with core memory allocation strategies — no backend, no login, no installation required.

The simulator runs entirely in the browser using vanilla HTML, CSS and JavaScript. All state is managed locally, ensuring privacy and offline usability.

Features at a glance

  • First Fit, Best Fit and Worst Fit allocation
  • Step-by-step animated visualization
  • Algorithm comparison mode
  • JSON / CSV configuration import
  • Execution log and results summary
  • Fully responsive, zero dependencies

Getting Started

The simulator loads with demo data. Simply click Run Simulation to see an instant result. Modify blocks and processes using the + / × controls, then re-run.

File Import Format

JSON: {"blocks":[100,200],"processes":[50,80]}
CSV: Row 1 = block sizes, Row 2 = process sizes, comma-separated.
